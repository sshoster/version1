# Deploying Bridge AI publicly — Render + MongoDB Atlas + Cloudflare R2

One Docker container (backend serving the Angular app, API, and WebSocket on one origin),
a managed MongoDB replica set, and S3-compatible object storage. Total cost to start: **$0**
(Render free tier sleeps after ~15 min idle; upgrade to Starter ~$7/mo for always-on).

Everything below is account setup you do in a browser; the repository already contains the
packaging (`Dockerfile.fullstack`) and the Render blueprint (`render.yaml`).

---

## 1. MongoDB Atlas (database, free)

1. Create an account at https://www.mongodb.com/cloud/atlas/register.
2. Create a **free M0 cluster** (pick a region close to your Render region, e.g. Frankfurt).
3. Database Access → **Add New Database User** → username + strong password (Read and write to any database).
4. Network Access → **Add IP Address** → `0.0.0.0/0` (Render's outbound IPs vary; auth + TLS protect the cluster. You can tighten later with Render static outbound IPs on paid plans.)
5. Cluster → **Connect → Drivers** → copy the connection string and set the database name:

   ```
   mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/debate?retryWrites=true&w=majority
   ```

   This is your `MONGODB_URI`. (M0 is a replica set — transactions work.)

## 2. Cloudflare R2 (file storage, free tier)

1. Create an account at https://dash.cloudflare.com → R2 Object Storage (requires adding a payment
   method, but 10GB storage + free egress are within the free tier).
2. **Create bucket** — name e.g. `bridge-ai-files`. Keep it private (default).
3. R2 → **Manage R2 API Tokens → Create API Token** → permission "Object Read & Write", scoped to
   the bucket. Save the **Access Key ID** and **Secret Access Key**.
4. Note your account id from the R2 endpoint shown, e.g. `https://<accountid>.r2.cloudflarestorage.com`.

   → `S3_BUCKET=bridge-ai-files`, `S3_ENDPOINT=https://<accountid>.r2.cloudflarestorage.com`,
   `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_REGION=auto`.

## 3. Render (compute + TLS + domain)

1. Create an account at https://render.com and connect your GitHub.
2. **New → Blueprint** → select the `sshoster/version1` repository → Render reads `render.yaml`.
3. Fill in the environment values it asks for:

   | Variable | Value |
   | --- | --- |
   | `APP_ENCRYPTION_KEY` | output of `openssl rand -base64 32` (or PowerShell: `[Convert]::ToBase64String((1..32 \| %{Get-Random -Max 256}))` — must decode to exactly 32 bytes) |
   | `MONGODB_URI` | from step 1 |
   | `APP_BASE_URL` | `https://<service-name>.onrender.com` (you can edit after the first deploy once you know the URL) |
   | `S3_*` | from step 2 |
   | `OPENAI_API_KEY` | your key (or set `LLM_PROVIDER=fake` to run without AI costs) |
   | `SMTP_*` / `MAIL_FROM` | only if you flip `MAIL_ENABLED` to `true` (Gmail app password) |

   `JWT_SECRET` is generated by Render automatically.
4. **Apply** — the first build takes ~10 minutes (npm + Gradle inside Docker). The service is
   healthy when `/actuator/health` reports UP.
5. Verify: open `https://<service>.onrender.com` — the app should load, register a user, create a
   discussion, invite from a second browser.
6. If `APP_BASE_URL` was a guess, set it to the real URL now (Environment tab) so invitation
   links/emails point at the right place, and redeploy.

### Custom domain (optional)

Render service → Settings → Custom Domains → add your domain, create the shown CNAME at your DNS
provider. TLS is automatic. Update `APP_BASE_URL` accordingly.

## 4. Post-deploy checklist

- [ ] Register two real users, run the full flow (share → assistants → proposal → approvals → documents).
- [ ] File upload/download works (proves R2 credentials).
- [ ] Set an OpenAI **usage limit** (platform.openai.com → Billing) as a cost safety net.
- [ ] Atlas: enable backup snapshots (M0 has limited backup; M2+ for scheduled backups).
- [ ] Keep `SEED_DEMO` unset in production.

## Operational notes

- **One instance by design** — presence, rate limiting, and outbox claiming are in-memory. Do not
  scale horizontally without replacing those seams (Redis) first.
- **Free-tier sleep**: the free Render plan spins down after idle; the first request then takes
  ~1 min and WebSocket sessions drop on sleep. Starter ($7/mo) removes this.
- **Logs/metrics**: Render dashboard streams stdout (our structured logs, content-free);
  `/actuator/health` is the health probe.
- **Migrating to AWS later**: the same image runs on ECS Fargate behind an ALB; swap R2 for S3 by
  changing `S3_ENDPOINT`/keys; Atlas already runs on AWS regions. No code changes expected.
